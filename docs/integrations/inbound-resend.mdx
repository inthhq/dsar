`@dsar/inbound-resend` accepts Resend `email.received` webhook events and maps them into canonical DSAR request capture input.

## Configuration

Required:

- `webhookSecret`: Resend webhook secret used for svix signature verification.

Optional:

- `apiKey`: Resend API key (needed only when `fetchEmailContent` is enabled).
- `fetchEmailContent`: fetch plain text / html body via Resend receiving API.
- `routeMap`: recipient address routing map:
  - key: inbound recipient address (lowercased)
  - value: `{ tenantId, workspaceId?, jurisdiction }`
- `defaultRoute`: fallback route for OSS quick-start.

Example:

```ts
import { makeResendInboundAdapter } from "@dsar/inbound-resend";

const inbound = makeResendInboundAdapter({
	webhookSecret: process.env.RESEND_WEBHOOK_SECRET!,
	fetchEmailContent: true,
	apiKey: process.env.RESEND_API_KEY,
	routeMap: {
		"privacy@tenant-a.example": {
			tenantId: "tenant-a",
			jurisdiction: "uk",
		},
	},
	defaultRoute: {
		tenantId: "tenant-default",
		jurisdiction: "eu",
	},
});
```

## Backend Wiring

Register inbound adapter with `dsarInstance`:

```ts
const runtime = dsarInstance({
	adapters: {
		inbound,
		notifications: "stub",
		storage: "stub",
	},
});
```

Webhook endpoint:

- `POST /webhooks/inbound/resend`
- required headers:
  - `svix-id`
  - `svix-timestamp`
  - `svix-signature`

## Intake Mapping

Inbound webhook events are mapped to request capture payload:

- `jurisdiction`: from recipient route resolution
- `intakeSource.type`: `inbound_email`
- `intakeSource.receivedAt`: authoritative email timestamp
- `intakeSource.rawContextRef`: Resend `email_id` or `message_id`
- `requestor.email`: parsed sender email

## Idempotency and Retries

- Idempotency key is derived as:
  - `inbound-resend:{sourceId}:{tenantId}:{workspaceId|*}`
- `captureRequestLifecycle()` dedupes existing requests by `capture.idempotencyKey`.
- Replayed webhook deliveries return the original request id.

## Failure Modes

- Invalid signature or malformed payload: `REQUEST_VALIDATION_FAILED`.
- Missing recipient route and no default route: `REQUEST_VALIDATION_FAILED`.
- Non-DSAR intent: accepted response with `status: ignored_non_dsar`.
